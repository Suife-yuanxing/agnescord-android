## 一、A3：键盘弹出时输入框无法浮到键盘上方 🔴

### 1.1 根因分析

**源码现状**：
- AndroidManifest.xml L19：`android:windowSoftInputMode="adjustResize"` ✅
- 聊天页.html L260-269：CSS `.phone.keyboard-open .input-bar { position:fixed; bottom:0; ... }`
- 聊天页.html L1281-1295：focus/blur 事件 → `classList.add/remove('keyboard-open')`

**已尝试方案均失败的原因**：
1. **CSS `position:fixed` 方案**：`.input-bar` 在 `.phone`（position:fixed 容器）内部，子元素的 `position:fixed` 脱离父容器相对于 viewport 定位，但 `left:0; right:0` 导致定位到屏幕边缘而非 phone 内。需改为 `bottom: <键盘高度>px` 而非固定 `bottom:0`。
2. **visualViewport 方案**：Android 16 Oppo ColorOS 的 WebView 对 `visualViewport` API 支持不完整，resize 事件可能不触发或值不准确。
3. **核心问题**：无法获取键盘的精确高度（px），因此无法计算输入栏应上移多少。

### 1.2 推荐方案：Native 层键盘高度检测 + JS translateY

**原理**：Android `ViewTreeObserver.OnGlobalLayoutListener` 可在键盘弹出/收起时精确获取 WebView 可视区域变化，计算出键盘高度（px），通过 `NativeBridge` 传给 JS，JS 用 `transform: translateY()` 将输入栏上移。

**Java 端（MainActivity.java，`configureWebView` 末尾追加）**：
```java
// A3：键盘高度检测 — ViewTreeObserver 精确获取键盘弹出高度
webView.getViewTreeObserver().addOnGlobalLayoutListener(new ViewTreeObserver.OnGlobalLayoutListener() {
    private int lastKeyboardH = 0;
    @Override
    public void onGlobalLayout() {
        Rect r = new Rect();
        webView.getWindowVisibleDisplayFrame(r);
        int screenH = webView.getRootView().getHeight();
        int keyboardH = screenH - r.bottom;
        // 忽略导航栏高度（通常 < 150px）+ 去抖（变化 < 30px 不更新）
        if (Math.abs(keyboardH - lastKeyboardH) < 30) return;
        lastKeyboardH = keyboardH;
        // 传给 JS（仅非零时传值，零=键盘收起）
        webView.evaluateJavascript(
            "if(window._onKeyboardChanged){window._onKeyboardChanged(" + keyboardH + ");}", null);
    }
});
```

**JS 端（聊天页.html，替换现有 A3 代码块 L1281-1295）**：
```js
// A3：Native 键盘高度 → translateY 输入栏
(function() {
    var inputBar = document.querySelector('.input-bar');
    if (!inputBar) return;
    window._onKeyboardChanged = function(keyboardH) {
        if (keyboardH > 100) {
            // 键盘弹出：上移输入栏到键盘上方，保留少量间距
            inputBar.style.transform = 'translateY(-' + (keyboardH - 12) + 'px)';
            inputBar.style.transition = 'transform 0.15s ease-out';
            // 滚动消息列表到底
            var list = document.getElementById('messageList');
            if (list) setTimeout(function(){ list.scrollTop = list.scrollHeight; }, 200);
        } else {
            // 键盘收起：恢复原位
            inputBar.style.transform = '';
            inputBar.style.transition = 'transform 0.2s ease-out';
        }
    };
})();
```

**同时移除**：
- CSS `.phone.keyboard-open .input-bar` 规则（L260-269）
- JS focus/blur 事件监听器（L1281-1295）
- 这些改为 `_onKeyboardChanged` 接管

### 1.3 可行性审计

| 维度 | 评估 | 说明 |
|------|:----:|------|
| **技术正确性** | ✅ | `ViewTreeObserver.OnGlobalLayoutListener` 是 Android 官方推荐的键盘检测方式，Android 4.0+ 通用 |
| **Oppo 兼容性** | ✅ | 此方案直接从 View 层获取尺寸，不依赖 `adjustResize` 是否正确传播到 WebView CSS。Oppo ColorOS 的 WebView 实现不会阻止 `getWindowVisibleDisplayFrame` |
| **性能** | ✅ | `OnGlobalLayoutListener` 仅在布局变化时触发（键盘弹出/收起约 2-4 次），每次仅做整数比较 + evaluateJavascript |
| **副作用** | ✅ | `transform: translateY` 不影响文档流，不会触发 reflow，其他元素位置不受影响 |
| **降级** | ✅ | 如果用户未授予 NativeBridge 权限或 WebView 未就绪，输入栏维持原位（现有行为），不会更差 |
| **已知风险** | ⚠️ | ① 首次键盘弹出时 listener 可能触发多次（动画帧），已通过 30px 去抖缓解；② 横屏/分屏模式下 `screenH` 可能不准——此时返回的 keyboardH 可能为负数，`if (keyboardH > 100)` 守卫排除 |
| **替代方案** | — | `adjustPan` 变更简单但副作用大（标题栏跟随滚动消失），不推荐 |

## 二、A7：语音消息跳转后消失 / 无法点击播放 🔴

### 2.1 根因分析

代码位于聊天页.html L1298-1388，存在 **3 个独立 bug**：

**Bug 1：`onclick` 内嵌 `addEventListener` 在 innerHTML 中无效**（L1360-1361）
```js
// ❌ 错误：addEventListener 嵌套在 innerHTML 的 onclick 字符串中无法注册
row.innerHTML = '...onclick="var a=this.querySelector(\'audio\');...' +
    'this.querySelector(\'audio\').addEventListener(\'ended\',function(){...});' + '">'
```
`innerHTML` 中的 `onclick` 字符串只执行一次（点击时）。其中调用的 `addEventListener` 确实会执行，但脚本字符串中的引号转义极易出错且难以调试。

**Bug 2：localStorage 恢复条件过于严格**（L1378-1386）
```js
function loadSavedVoices() {
    var msgs = JSON.parse(localStorage.getItem(VOICE_KEY) || '[]');
    if (!msgs.length) return;
    var list = document.getElementById('messageList');
    if (!list || list.children.length > 0) return; // ← 只有空列表才恢复！
    msgs.forEach(function(m) { appendVoiceBubble(m.seconds, m.src); });
}
```
当用户发送文字消息后切走再回来，`list.children.length > 0`（有文字消息），语音消息不会被恢复。

**Bug 3：语音数据无后端持久化**
语音以 base64 data URL 存 localStorage。两个问题：
- base64 数据大：1 秒 AMR ~1KB，60 秒 ~60KB。localStorage 上限 5-10MB
- **跨设备/清缓存后丢失**：用户换手机或清 WebView 数据后语音消失

### 2.2 推荐方案：三重修复

#### 修复 A：重写 `appendVoiceBubble` — 用事件委托替代内联 onclick

```js
function appendVoiceBubble(seconds, audioSrc) {
    var list = document.getElementById('messageList');
    if (!list) return;
    var row = document.createElement('div');
    row.className = 'msg-row me voice-msg';
    row.setAttribute('data-voice-src', audioSrc);
    row.setAttribute('data-voice-seconds', seconds);
    row.innerHTML =
        '<div class="msg-avatar user">我</div>' +
        '<div class="bubble me voice-bubble" style="padding:8px 14px;display:flex;align-items:center;gap:8px;cursor:pointer;min-width:80px;">' +
        '<span class="voice-play" style="font-size:16px;color:#F472B6;">▶</span>' +
        '<span class="voice-time" style="font-size:13px;color:#3A2030;min-width:30px;">' + seconds + '"</span>' +
        '</div>';
    // 将 audio 元素存为 row 的属性，避免 innerHTML 中构造
    var audio = document.createElement('audio');
    audio.src = audioSrc;
    audio.preload = 'auto';
    audio.style.display = 'none';
    row.appendChild(audio);
    list.appendChild(row);
    list.scrollTo({ top: list.scrollHeight, behavior: 'smooth' });
}

// 事件委托：在 messageList 上统一处理语音气泡点击
document.getElementById('messageList').addEventListener('click', function(e) {
    var bubble = e.target.closest('.voice-bubble');
    if (!bubble) return;
    var row = bubble.closest('.voice-msg');
    var audio = row ? row.querySelector('audio') : null;
    var playIcon = bubble.querySelector('.voice-play');
    if (!audio) return;
    if (audio.paused) {
        audio.play();
        if (playIcon) playIcon.textContent = '⏸';
    } else {
        audio.pause();
        if (playIcon) playIcon.textContent = '▶';
    }
    audio.onended = function() {
        if (playIcon) playIcon.textContent = '▶';
    };
});
```

#### 修复 B：localStorage 恢复逻辑修正

```js
function loadSavedVoices() {
    try {
        var msgs = JSON.parse(localStorage.getItem(VOICE_KEY) || '[]');
        if (!msgs.length) return;
        var list = document.getElementById('messageList');
        if (!list) return;
        // 只恢复尚未在列表中的语音（根据时间戳去重）
        var existingTimestamps = new Set();
        list.querySelectorAll('.voice-msg').forEach(function(row) {
            var ts = row.getAttribute('data-voice-time');
            if (ts) existingTimestamps.add(parseInt(ts));
        });
        msgs.forEach(function(m) {
            if (!existingTimestamps.has(m.time)) {
                appendVoiceBubble(m.seconds, m.src);
            }
        });
    } catch(e) {}
}
```

并在 `appendVoiceBubble` 末尾保存时加上时间戳：
```js
row.setAttribute('data-voice-time', Date.now());
// 保存到 localStorage...
msgs.push({ seconds: seconds, src: audioSrc, time: Date.now() });
```

#### 修复 C：后端语音上传端点（长期方案）

参照已有的 `POST /messages/upload-image` 模式，添加：
- **后端** `chat.py`：`POST /messages/upload-voice`，接收 multipart 音频文件，保存到 `/home/ubuntu/deepseek-data/voices/`，返回 `{"voice_url": "/data/voices/xxx.amr"}`
- **前端** `api.js`：新增 `API.uploadChatVoice(botId, blob)` 方法
- 录音结束后上传到后端 → 拿到持久 URL → 语音气泡引用持久 URL 而非 base64

**实施顺序**：优先做修复 A+B（纯前端，立即可验证），修复 C 作为后续增强。

## 四、B4 用量明细 + 添加 Key 按钮（同一根因） 🔴

### 4.1 根因分析

API Key管理.html L303-472 中，所有逻辑包裹在一个 IIFE 内。关键函数通过 `window.xxx = function()` 暴露到全局。

**问题**：如果 IIFE 内 **任何同步代码抛出异常**（在 `window.loadUsageDetail`/`window.toggleNewForm` 赋值之前），这两个全局函数就是 `undefined`。

最可能的异常源：
1. **`API.getApiKeyUsageSummary()` 在 API 未登录时返回 rejected Promise** → `.catch(function(){})` 已兜底，不会抛出
2. **`API.getApiKeys()` 同理** → 已兜底
3. **但如果在 Promise 链之前有同步错误**（如 `_esc` 函数收到非预期数据）→ IIFE 中断

根本问题：IIFE **没有外层 try/catch**！

### 4.2 推荐方案

#### 修复 A：IIFE 加 try/catch 兜底

```js
(function() {
  'use strict';
  try {
    // ... 所有现有逻辑 ...
  } catch(e) {
    console.error('[API Key管理] 初始化失败:', e);
    // 确保关键函数至少有降级定义
    if (typeof window.switchTab !== 'function') {
      window.switchTab = function(tab, btn) {
        document.querySelectorAll('.tab-btn').forEach(function(b){ b.classList.remove('active'); });
        if (btn) btn.classList.add('active');
        document.getElementById('keysTab').style.display = tab === 'keys' ? '' : 'none';
        document.getElementById('usageTab').style.display = tab === 'usage' ? '' : 'none';
      };
    }
    if (typeof window.toggleNewForm !== 'function') {
      window.toggleNewForm = function() {
        var form = document.getElementById('newKeyForm');
        if (form) form.classList.toggle('show');
      };
    }
    if (typeof window.createKey !== 'function') {
      window.createKey = function() { alert('API Key 功能暂不可用，请刷新重试'); };
    }
  }
})();
```

#### 修复 B：HTML onclick 改为事件委托（治本）

当前问题：HTML 中 `onclick="toggleNewForm()"` 依赖全局函数存在。如果用事件委托绑定，不依赖全局作用域：

```js
// 替换 <button onclick="toggleNewForm()"> 为 <button id="addKeyBtn">
// 在 IIFE 内：
var addBtn = document.querySelector('.add-btn');
if (addBtn) {
    addBtn.addEventListener('click', function() {
        document.getElementById('newKeyForm').classList.toggle('show');
    });
}
```

同时移除 HTML 中的 `onclick="toggleNewForm()"` 和 `onclick="createKey()"`，全部改用 `addEventListener`。

#### 修复 C：switchTab 防御性检查

```js
window.switchTab = function(tab, btn) {
```

## 五、C6：无法弹出系统权限请求对话框 🔴

### 5.1 根因分析

**已尝试方案**：
1. `registerForActivityResult(ActivityResultContracts.RequestPermission())` → ❌
2. `ActivityCompat.requestPermissions` + `onRequestPermissionsResult` → ❌

**当前代码审查**（MainActivity.java L262-291）：
- `NativeBridge.requestPermission()` 简化权限名称（"录音" → `RECORD_AUDIO`）✅
- `ContextCompat.checkSelfPermission` 先检查已有权限 ✅
- `ActivityCompat.requestPermissions` 申请新权限 ✅
- `onRequestPermissionsResult` 回调 JS ✅

代码逻辑本身正确（标准 AndroidX 权限请求模式）。在 Oppo ColorOS 上失败的可能原因：

1. **ColorOS 权限管控增强**：Oppo 的 ColorOS 13+ 可能拦截来自 WebView 上下文的权限请求（安全策略）
2. **`launchMode="singleTask"`**：如果 Activity 被复用，`onRequestPermissionsResult` 可能投递到旧实例
3. **WebView 不在前台**：`requestPermissions` 需要 Activity 在前台，WebView 内 JS 调用的时机可能不满足
4. **权限已在 Manifest 声明但被 Oppo 系统级禁用**：ColorOS 有"权限管理"独立层

### 5.2 推荐方案：双路径策略

#### 路径 1（开发调试）：adb 直接授权
```bash
adb shell pm grant com.deepseekqq.agnescord android.permission.RECORD_AUDIO
adb shell pm grant com.deepseekqq.agnescord android.permission.CAMERA
adb shell pm grant com.deepseekqq.agnescord android.permission.POST_NOTIFICATIONS
adb shell pm grant com.deepseekqq.agnescord android.permission.READ_MEDIA_IMAGES
```
验证功能可用后再解决弹窗问题。

#### 路径 2（用户面）：权限被拒时跳转系统设置

在 `NativeBridge.requestPermission` 中，如果 `ActivityCompat.requestPermissions` 失败或被用户拒绝，提供 fallback：

```java
@JavascriptInterface
public void requestPermission(final String permission) {
    runOnUiThread(() -> {
        String perm = resolvePermission(permission); // 现有的名称映射
        if (perm == null) {
            webView.evaluateJavascript("if(window._permissionCallback){window._permissionCallback(false);}", null);
            return;
        }
        if (ContextCompat.checkSelfPermission(MainActivity.this, perm) == PackageManager.PERMISSION_GRANTED) {
            webView.evaluateJavascript("if(window._permissionCallback){window._permissionCallback(true);}", null);
            return;
        }
        // 检查是否应显示权限说明（用户之前拒绝过）
        if (ActivityCompat.shouldShowRequestPermissionRationale(MainActivity.this, perm)) {
            // 用户之前拒绝过 → 直接跳系统设置（ColorOS 可能阻止二次弹窗）
            openAppSettings();
            webView.evaluateJavascript("if(window._permissionCallback){window._permissionCallback(false);}", null);
        } else {
            // 首次请求 → 弹系统对话框
            ActivityCompat.requestPermissions(MainActivity.this, new String[]{perm}, 100);
        }
    });
}

private void openAppSettings() {
    Intent intent = new Intent(android.provider.Settings.ACTION_APPLICATION_DETAILS_SETTINGS);
    intent.setData(android.net.Uri.parse("package:" + getPackageName()));
    startActivity(intent);
    Toast.makeText(this, "请在设置中手动开启权限", Toast.LENGTH_LONG).show();
}
```

## 七、D1：删除 Bot 后短暂卡住无法立即删下一个 🔴

### 7.1 根因分析

我的Bot.html L194-200 `confirmDelete` 函数：

```js
window.confirmDelete = function(botId, botName) {
    if (confirm(...)) {
      API.deleteBot(botId).then(function() {
        API.listBots().then(function(d) { renderBots(d.bots); });
        // ❌ BUG：renderBots 后没有调用 bindSwipe()！
      })...
    }
};
```

**连锁问题**：
1. `renderBots()` 替换整个 `botList` 的 innerHTML → 所有旧 DOM 元素（含 touch 事件监听器）被销毁
2. 新 DOM 元素没有绑定 touch 事件 → 无法左滑
3. 用户尝试左滑新卡片时无反应 → 感知为"卡住"
4. 如果用户在 401 返回后快速连续点击，旧事件监听器可能因为异步未清理而累积

### 7.2 推荐方案

**最小修复**（1 行改动）：

```js
window.confirmDelete = function(botId, botName) {
    if (confirm('确定删除 Bot「' + botName + '」吗？\n此操作不可撤销，聊天记录将一并删除。')) {
      API.deleteBot(botId).then(function() {
        API.listBots().then(function(d) { 
            renderBots(d.bots); 
            bindSwipe();  // ← 修复：重新绑定左滑手势
        });
      }).catch(function(err) {
        alert('删除失败：' + (err.message || '未知错误'));
      });
    }
};
```

**增强修复**（`bindSwipe` 开头先重置所有状态）：

```js
function bindSwipe() {
    // D1：先重置所有卡片滑动状态，避免事件累积
    document.querySelectorAll('.bot-card-wrap').forEach(function(wrap) {
        var card = wrap.querySelector('.bot-card[data-bot-id]');
        var actions = wrap.querySelector('.swipe-actions');
        if (card) card.style.transform = '';
        if (actions) actions.style.display = 'none';
    });
    // ... 现有绑定逻辑 ...
}
```

## 十一、聊天背景：选黑色后其他颜色无法切换 🟡

### 11.1 根因分析

聊天页.html 和 app.js 各有一套背景管理函数：

| 函数 | 位置 | 触发时机 |
|------|------|---------|
| `applyChatBgToOverlay` | 聊天页.html L708 | 用户点击 bg-picker → `setChatBg` → 直接调用 |
| `applyChatBgGlobal` | app.js L67 | 页面加载时 `loadChatBgGlobal` + 跨 tab `storage` 事件 |
| `loadChatBg` | 聊天页.html L808 | 页面加载时 + 跨 tab `storage` 事件 |

**问题**：页面加载时 **两个函数都运行**（app.js 的 `loadChatBgGlobal` + 聊天页的 `loadChatBg`），但它们逻辑有细微差异——`applyChatBgToOverlay` 在 dark-mode 下的背景重置行为与 `applyChatBgGlobal` 不同。

**关键 bug**：在 `applyChatBgToOverlay` 中：
```js
phone.style.background = '';
if (!phone.classList.contains('dark-mode')) phone.style.background = '#FFF5F7';
```
如果 dark-mode 开启，`phone.style.background = ''`（空内联样式），CSS `.phone.dark-mode { background: #1A1A2E }` 生效。然后设置渐变 `phone.style.background = 'linear-gradient(...)'` 应覆盖 CSS。

但问题可能出在：`setChatBg` 调用 `localStorage.setItem` → **storage 事件在同一页面的另一个 listener 触发**？不，storage 事件只在其他 tab 触发。但同一页面有两个 storage listener（一个在聊天页 L1147，一个在 app.js L124），如果用户在另一个聊天页 tab 切换背景，两个 listener 都会在**当前** tab 执行，可能导致竞态。

**更可能的根因**：`loadChatBgGlobal`（app.js L97-121）在非聊天页也运行。当用户从聊天页导航到其他页时，`loadChatBgGlobal` 会把非聊天页的 `.phone` background 设置为空 + 默认。但导航回来时，`loadChatBg` 重新应用聊天背景。如果 dark-mode 在此期间被切换，可能出现状态不一致。

### 11.2 推荐方案：统一背景管理

#### 步骤 1：合并两个函数
删除 `applyChatBgToOverlay`（聊天页.html L708-749），统一使用 `applyChatBgGlobal`（app.js 中已有）。

聊天页的 `setChatBg` 改为调用全局函数：
```js
function setChatBg(bg, el) {
    var bgData = { type: 'default', value: '' };
    if (bg === '📷') { ... return; }
    else if (bg) {
        bgData = { type: bg.startsWith('#') ? 'dark' : 'gradient', value: bg };
    }
    localStorage.setItem(CHAT_BG_KEY, JSON.stringify(bgData));
    // 统一使用 app.js 的 applyChatBgGlobal
    applyChatBgGlobal(bgData, document.getElementById('phoneFrame'), document.getElementById('chatBg'));
    // ...高亮选中...
}
```

#### 步骤 2：处理 dark-mode 背景覆盖
在 `applyChatBgGlobal` 中，用 `setProperty('background', ..., 'important')` 确保内联样式覆盖 CSS 类：
```js
function applyChatBgGlobal(bgData, phone, bgEl) {
    // Reset
    phone.style.setProperty('background', '', 'important');
    if (!phone.classList.contains('dark-mode')) phone.style.background = '#FFF5F7';
    // ... bgEl reset ...
    
    if (!bgData || bgData.type === 'default' || !bgData.value) return;
    
    // 使用 setProperty + important 确保覆盖 dark-mode CSS
    if (bgData.type === 'custom') {
        phone.style.setProperty('background', 'url(' + bgData.value + ') center/cover no-repeat', 'important');
    } else {
        phone.style.setProperty('background', bgData.value, 'important');
    }
    // ...
}
```

#### 步骤 3：清理重复的 storage listener
删除聊天页.html L1147-1149 的 storage listener（app.js L124 已有全局版本），只保留 app.js 中的。

#### 步骤 4：加日志诊断
```js
// 在 setChatBg 末尾加：
console.log('[chatBg] set:', bgData.type, bgData.value ? bgData.value.substring(0,30) : 'default',
    'phone.bg:', document.getElementById('phoneFrame').style.background);
```

### 11.3 可行性审计

| 维度 | 评估 | 说明 |
|------|:----:|------|
| **函数合并** | ✅ | `applyChatBgGlobal` 是 `applyChatBgToOverlay` 的超集，直接替换无功能损失 |
| **setProperty important** | ✅ | 原生 API，WebView 4.4+ 均支持 |
| **storage listener 清理** | ✅ | 消除重复触发，行为更可预测 |
